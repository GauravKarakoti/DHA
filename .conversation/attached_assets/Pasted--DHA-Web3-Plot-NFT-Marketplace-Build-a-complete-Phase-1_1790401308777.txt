# DHA — Web3 Plot NFT Marketplace

Build a complete Phase 1 Web3 NFT marketplace application called **DHA**.

DHA is a housing-society-themed Web3 learning project where users can mint digital plot NFTs. Each plot is represented by an ERC-721 NFT containing metadata such as plot number, block, area, and location.

This is a **learning project**. The NFTs represent digital/virtual plots and must NOT be presented as legally representing ownership of real-world property.

The goal of Phase 1 is:

> Connect wallet → Mint a Plot NFT → Store metadata → Deploy ERC-721 contract → Display NFTs in a polished marketplace-style UI → View NFT details.

Do NOT implement auctions or marketplace buying/selling yet. The architecture should make it easy to add those features later.

# 11. Solidity Contract

Create:

```text
contracts/DHAPlotNFT.sol
```

Implement a proper ERC-721 contract using OpenZeppelin.

The contract should:

* inherit ERC721
* use Ownable where appropriate
* maintain an incremental token ID
* support minting
* support tokenURI
* emit useful events
* prevent invalid minting
* expose useful read functions

Suggested concept:

```solidity
contract DHAPlotNFT is ERC721, Ownable {
    uint256 private _nextTokenId;

    struct Plot {
        uint256 plotNumber;
        string blockName;
        uint256 area;
        string location;
        string metadataURI;
    }

    mapping(uint256 => Plot) public plots;

    ...
}
```

But design the contract properly rather than blindly copying this structure.

# 12. Mint Function

Implement a function similar to:

```solidity
function mintPlot(
    address to,
    string memory tokenURI,
    uint256 plotNumber,
    string memory blockName,
    uint256 area,
    string memory location
) external returns (uint256)
```

The exact signature can be improved if needed.

Requirements:

* Token IDs should increment automatically.
* Each token must have unique ownership.
* Metadata URI must be associated with the token.
* Plot information should be stored on-chain where appropriate.
* Emit an event such as:

```solidity
event PlotMinted(
    uint256 indexed tokenId,
    address indexed owner,
    uint256 plotNumber
);
```

Make the contract easy to extend later.

# 13. Important Minting Design

Because this is a learning project, allow users to mint their own plot NFTs.

However, prevent accidental duplicate plot numbers if possible.

Implement a mapping:

```solidity
mapping(uint256 => bool) public plotNumberExists;
```

Before minting:

```text
if plot number already exists
    revert
```

This means Plot #001 cannot be minted twice.

Keep this logic separate from future marketplace logic.

# 21. Security

Follow basic Web3 security practices.

Do NOT:

* hardcode private keys
* expose RPC secrets
* trust frontend-only ownership checks
* use `tx.origin`
* use unsafe external calls unnecessarily
* implement custom ERC721 logic when OpenZeppelin already provides it
* use `unchecked` arithmetic unless justified

Use OpenZeppelin's audited ERC-721 implementation.

Use Solidity compiler version compatible with the installed OpenZeppelin version.
